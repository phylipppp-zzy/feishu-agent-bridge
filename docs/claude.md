# 飞书 ↔ Claude Code 桥接

本仓库除了 Codex 桥接，还包含一个独立的 Claude Code 桥接。它把本机 Claude Code 的会话（VS Code 扩展和终端里的都算）同步到一个飞书私密话题群，方便在手机上查看。在会话话题里直接回复就能继续这个会话，也可以从飞书新建会话；Claude 仍然在这台电脑上运行，使用你本机的 `claude` 和设置。

Claude 桥接和 Codex 桥接互不影响：各用一个飞书应用、一个私密群、一个 systemd 服务和一份配置。两者可以同时运行。

## 在飞书里看到什么

- **一个会话一个话题。** 根卡片显示标题（`/rename` 起的名字优先，其次是 Claude 自动生成的标题）、项目目录、来源（VS Code、终端或飞书）、模型、最近的权限模式、当前状态和最后活动时间，并给出 `claude --resume <会话 ID>` 命令。根卡片上的按钮见“从飞书继续对话”一节。
- **一轮对话一张卡片。** 先发一条提问（例如“VS Code：修复登录页的样式”），再发一张 Claude 卡片。卡片里是 Claude 的文字回复，工具调用折叠在“执行记录”里（例如 `✓ Bash · npm test`、`✗ Edit · src/a.ts`）。进行中的卡片会随日志更新，结束后标题显示“已完成 · 用时 …”。从飞书话题里发起的一轮，你发的那条消息就是提问，桥接不再另发提问行。Claude 工作期间收到的补充消息（无论在 VS Code、终端还是飞书中发送）会以“— 补充：… —”显示在当前这一轮的卡片里。
- **不是你输入的轮次也会显示**，并注明来源：子 agent 回报、后台任务通知、斜杠命令（如 `/model`）。
- **状态与提醒。** 根卡片上的状态来自 Claude Code 的 hooks：VS Code 或终端中“运行中”“等待你处理”“已打开（空闲）”“未在本机打开”。会话在本机等待你确认权限时，话题里会收到一条提醒，手机上会有推送。会话正在从飞书继续时，根卡片显示的是飞书中的状态，见“从飞书继续对话”一节。
- **中途断掉的轮次**（会话被关掉、请求失败、没有完成记录）在本机不再运行、半小时没有新记录后显示为“未完成”。
- **长回复**：卡片只保留最后约 18,000 字，完整内容会以 Markdown 附件发到话题里。

## 历史会话

- 绑定时，最近 `HISTORY_DAYS`（默认 3）天有活动的会话会自动建话题，只显示**最后一轮**；更早的内容在话题里点“导出完整记录”或发送 `/export`，会收到一个 Markdown 文件。
- 更早的会话只建索引不建话题。在“最近会话”里搜索后点“打开”，会新建话题并显示最后一轮。
- 绑定后新开始的会话，从第一轮开始完整显示。
- 已有话题的会话出现新活动时，只追加新的轮次。

## 只同步部分目录（可选）

默认同步所有目录下的会话。只想同步某个文件夹及其子目录下的对话时，设置 `SYNC_DIRS`：

```bash
# 方式一：通过安装器（可写多个 --sync-dir；会复用已有的飞书应用和 hook）
./install-claude.sh --sync-dir ~/usr/zhangzy/workspace --sync-dir /data/projects
# 恢复同步全部目录
./install-claude.sh --sync-all

# 方式二：直接编辑环境文件，然后重启服务
#   ~/.config/feishu-claude-bridge/env 中写：SYNC_DIRS="/home/sar/usr/zhangzy/workspace,/data/projects"
systemctl --user restart feishu-claude-bridge.service
```

- 判断依据是会话的工作目录（Claude Code 日志里记录的 `cwd`，即在 VS Code 中打开的文件夹或启动 `claude` 时所在的目录），不是 `~/.claude/projects` 下的文件夹名。路径支持 `~/` 开头，符号链接会解析成真实路径。
- 范围外的会话不建话题、不发卡片、不发提醒，也不出现在“最近会话”和搜索结果里。桥接仍会在本机读取它们的日志，只为了判断工作目录。
- 同步范围也限制飞书端的操作：工作目录不在范围内的会话不能从飞书继续；从飞书新建会话时，目录也必须在范围内。
- **话题的先后始终等于会话实际活动的先后。** 飞书只能在群里追加消息，不能插到过去的位置，所以桥接只在会话有新的一轮时才建话题（第一次绑定时按时间从早到晚建）。
- **范围扩大**：不为过去的活动补建话题。新纳入范围的会话会出现在“最近会话”里，需要时可以点“打开”；它下一次有新的一轮时，自动建话题，只显示这一轮及之后的内容。
- **范围缩小**：范围外的话题保留在群里，根卡片变灰并写明“已移出同步范围，不再更新”。范围再改回来时，根卡片恢复，之后的新内容继续追加到原话题里，不会重复建话题；范围外期间的对话不会补发。
- **清理范围外话题**：控制台（`/status`）在有范围外话题时会出现“清理范围外话题（N）”按钮。点击后先列出要清理的话题，确认后才撤回机器人在这些话题里发过的消息（根卡片、提问、回复卡片、附件、提醒）。你自己发的消息机器人无法撤回。飞书只允许机器人撤回企业“撤回时限”内的消息，**默认是发出后 24 小时**，企业管理员可以在管理后台把时限调长（最长可设为“任何时候”）；超过时限的消息撤不掉，结果卡片会逐条列出原因。根卡片撤不掉的话题会继续保留关联，范围恢复后仍在原话题里更新。
- 控制台会显示当前的同步范围。

## 从飞书继续对话

在会话的话题里直接回复，就会继续这个会话。桥接通过 Claude Agent SDK 在本机启动你自己的 `claude` 可执行文件（由环境变量 `CLAUDE_BIN` 指定），并加载你的用户、项目和本地设置（user、project、local），所以 `settings.json` 中的权限规则、`CLAUDE.md`、MCP 服务器和斜杠命令都与在终端里使用时一致。会话正在电脑上打开或运行时如何处理，见下文“手机与电脑之间切换控制”一节。

Claude 的执行记录照常通过会话日志同步到话题里，显示方式与本机的会话相同。回复正在生成时，卡片会实时显示 Claude 正在写的文字，大约每 1.5 秒更新一次。

你在话题里发的消息就是这一轮的提问，桥接不会再重复发一条“飞书：…”提问行。从卡片或群主消息新建的会话，以及分叉出的会话，第一条提问由桥接以“飞书：…”的形式发到新话题里。

- **Claude 正在工作时再发消息**：消息会在当前这一步（一次工具调用）结束后交给 Claude，相当于在终端里一边看一边补充说明。以 `>>` 开头的消息会排队，等这一轮结束后再发给 Claude，桥接会回复“已排队”。
- **图片**：话题消息里的图片会一起发给 Claude。每条消息最多 5 张，支持 PNG、JPEG、GIF、WebP，单张不超过 5 MB；不符合要求的图片不会发送，话题里会有提示。
- **话题中的命令**：只有 `/`、`/stop`、`/export`、`/ls` 和 `/deliver` 由桥接处理。单独发送 `/`，会在话题最新处再发一张与根卡片相同的控制卡片（停止本轮、权限模式、模型、导出、刷新），长话题里不用翻回顶部；`/stop` 停止当前回合；`/export` 导出完整记录；`/ls` 查看会话目录下的文件，`/deliver` 把本机文件发到话题里（见下文“查看和发送本机文件”）。其它所有内容，包括 `/compact` 等以 `/` 开头的内容，都原样交给 Claude。
- **根卡片**：显示飞书中的实时状态，即“飞书中运行中”“飞书中等待你处理”或“飞书中已连接（空闲）”。卡片上的按钮有“停止本轮”（这一轮进行中时显示）、“权限模式”、“模型”、“导出完整记录”和“刷新”。
- **不能继续的情况**：同步暂停时，不能从飞书继续或新建会话；会话的工作目录不在同步范围（`SYNC_DIRS`）内时，不能从飞书继续。

### 权限确认、提问与计划

从飞书继续的会话中，需要你处理的事项会以卡片发到话题里：

- **权限确认**：`settings.json` 中的权限规则照常生效；没有被规则覆盖的工具调用，会在话题里发一张确认卡片，可以选择“允许”“本会话都允许”或“拒绝”。“本会话都允许”只在本次会话内有效，不会写入 settings 文件；只有 Claude Code 给出了可以记住的规则时，才显示这个按钮。也可以直接在话题里回复文字，这等于拒绝，并把这段话告诉 Claude。
- **Claude 提问**（AskUserQuestion）：卡片上一次显示一个问题，答完再显示下一个。单选题可以直接点选项按钮；也可以回复选项编号（多选题用逗号分隔，例如 `1,3`），或者直接回复你自己的答案。不想回答时，点“不回答”。
- **计划**：计划模式下 Claude 提交计划（ExitPlanMode）时，话题里会发一张计划卡片，可以选择“执行，自动接受编辑”“执行，逐项确认”或“继续修改计划”，也可以直接回复修改意见。选择执行后，飞书续聊的权限模式会相应切换为“自动接受编辑”或“默认（逐项确认）”。

等待处理的请求在桥接重启后失效，这时再点卡片上的按钮，会提示“请求已失效”。

### 手机与电脑之间切换控制

- **切换到手机侧**：在话题里发消息，就切换到手机侧控制。桥接在本机用自己的 `claude` 进程接着这个会话运行，之后的消息直接发给 Claude，不再询问。
- **会话正在电脑上打开时**：如果会话正在 VS Code 或终端中打开，切换时话题里会提示一次：电脑上已打开的窗口不会显示手机上的对话；回到电脑后，重新打开这个会话（或运行 `claude --resume <会话 ID>`）即可看到并接着用。
- **电脑上这一轮还在运行时**：如果电脑上这一轮还在运行（或在等待确认），为避免两边同时写入同一个会话，消息不会立即发送。话题里会出现一张“电脑上这一轮还在运行”卡片，期间再发的消息也排在这张卡片里，按顺序发送。电脑上这一轮结束（或电脑上的会话关闭）后，这些消息自动发送，并切换到手机侧。卡片上有三个按钮：
  - **立即切换到手机**：不再等待，现在就发送。两边的内容可能交错。
  - **分叉到新话题**：把到目前为止的对话复制成一个新会话，在新话题里继续，电脑上的会话不受影响。原话题里会发一条指向新话题的链接；新话题根卡片的标题带“（分叉）”，并在“分叉自”一行显示原会话。
  - **取消**：排着的消息不发给 Claude。

  等待超过 2 小时电脑上这一轮仍未结束时，自动取消，消息不发送。电脑上在等待确认时，那一轮只能在电脑上处理。
- **切回电脑侧**：在电脑上（VS Code 或终端）对这个会话发出新的提问后，桥接自己的进程会退出（如果手机侧这一轮还在运行，则等它结束后再退出），话题里提示“已切回电脑侧控制”。之后在话题里再发消息，会重新切换到手机侧。
- 判断会话是否在电脑上打开、是否正在运行，依靠状态 hook。没有安装 hook（`--no-hooks`）时无法判断，消息总是直接发送。

### 飞书续聊的权限模式与模型

在根卡片上点“权限模式”或“模型”，可以设置这个会话从飞书继续时使用的权限模式、模型和推理强度。

- **权限模式**可选：默认（逐项确认）、自动接受编辑、计划模式（只读）、自动（由分类器判断）。飞书端不提供“跳过权限检查”（`bypassPermissions`）模式。
- 在飞书里选过模式时，使用选过的模式；没有选过时，沿用该会话最近使用的模式。如果最近的模式不在上面四种之内（例如跳过权限检查），则改用默认（逐项确认）。
- **模型**可选默认模型或列表中的模型；**推理强度**可选 low、medium、high、xhigh、max 或默认。
- 选“默认模型”或“默认强度”时，使用你在 Claude Code 设置（`~/.claude/settings.json`）中保存的模型和强度，从下一条消息开始生效；正在进行的这一轮结束后，桥接会换一个新的 `claude` 进程。这些设置只影响飞书里的对话，不会修改 VS Code 和终端的设置。
- 这些设置按会话分别保存。对正在运行的会话，修改立即生效。

## 从飞书新建会话

可以用以下任一方式新建会话：

- 在控制台或命令菜单中点“新建会话”，选择最近用过的目录，或者输入目录的绝对路径（可以用 `~`），再输入任务，点“开始”。
- 在群主消息中发送 `/new <目录> <任务>`。只发送 `/new` 会打开选择目录的卡片；发送 `/new <目录>` 会打开填写任务的卡片。
- 在群主消息中 @机器人 直接发送任务，再在机器人回复的卡片上点选目录，即可开始。需要在 30 分钟内点选目录。

目录必须存在，位于 `ALLOWED_ROOT`（默认是主目录）或它的子目录中，并且在同步范围（`SYNC_DIRS`）内；同步暂停时不能新建会话。桥接会立即为新会话创建话题，之后在这个话题里回复即可继续对话。

## 安装

前提：带 systemd 的 Linux（WSL2 可以，需要启用 systemd）、Node.js 22 及以上、能在终端运行的 `claude` 命令。从飞书继续或新建会话时，Claude Code 需要已经登录（在终端运行一次 `claude` 完成登录）；只同步会话不需要登录。

```bash
./install-claude.sh
```

安装器会依次：安装依赖并运行检查、测试和构建；显示飞书验证链接，确认后为你创建一个独立的“Claude Bridge”企业自建应用（不能与 Codex 桥接共用同一个应用）；写入权限为 `0600` 的 `~/.config/feishu-claude-bridge/env`（其中包括本机 `claude` 的路径和安装时 shell 的 `PATH`）；在 `~/.claude/settings.json` 中加入状态 hook（先备份原文件为 `settings.json.bak-<时间>`）；创建并启动用户服务 `feishu-claude-bridge.service`；最后运行自检。

仓库依赖 `@anthropic-ai/claude-agent-sdk`。安装依赖时，npm 会同时安装这个 SDK 自带的 Claude Code 二进制（可选依赖，约 230 MB）；桥接不使用它，而是使用 `CLAUDE_BIN` 指定的本机 `claude`。

常用选项：

- `--existing-app <cli_xxx>`：复用已有的飞书应用（用应用所有者账号扫码）。
- `--from-env`：使用手工填写的 `~/.config/feishu-claude-bridge/env`（参照 `deploy/env.claude.example`），不修改飞书后台。
- `--sync-dir <目录>`、`--sync-all`：设置或清除同步范围，见“只同步部分目录”一节。
- `--no-hooks`：不修改 `~/.claude/settings.json`。这时根卡片上没有本机的实时状态，收不到“等待你处理”的提醒；桥接也无法判断会话是否在电脑上运行，从飞书发的消息总是直接发送。对话内容照常同步。

安装完成后，在飞书创建一个私密话题群，把新机器人加进群，发送：

```text
@机器人 /bind <安装器显示的绑定码>
```

## 状态 hook 做了什么

安装器在 `~/.claude/settings.json` 的 `SessionStart`、`UserPromptSubmit`、`Stop`、`StopFailure`、`Notification`、`SessionEnd` 事件上各加一条命令，调用 `scripts/claude-hook.mjs`。它只把会话的状态（运行中、等待、空闲、关闭）、等待原因和 Claude Code 进程号写到 `~/.local/state/feishu-claude-bridge/presence/<会话 ID>.json`，不联网、不输出任何内容、出错也不影响 Claude Code，每次耗时约 20 毫秒。VS Code 扩展里的会话同样会触发这些用户级 hook。

桥接自己启动的 Claude Code 进程（从飞书继续、新建或分叉的会话）带有环境变量 `FEISHU_CLAUDE_BRIDGE=1`，hook 会跳过这些进程，所以这些会话不会被误判为“在本机打开”。

Claude Code 没有“权限请求已处理”的 hook 事件，所以你在本机批准后，桥接是根据会话日志里出现的新记录判断会话已恢复运行的。

移除这些 hook：

```bash
npm run uninstall:claude-hooks
```

## 群里的命令

群主消息（普通消息需要 @机器人，斜杠命令不需要）：

- `/`：命令菜单；`/help`、`帮助`：帮助。
- `/status`、`状态`：控制台（服务状态、已索引会话数、已建话题数、本机打开中的会话数）。
- `/new`：新建会话；`/new <目录>`、`/new <目录> <任务>` 的用法见“从飞书新建会话”一节。
- `/sessions`、`会话`、`最近`：最近会话；`/search <关键词>`：按标题、首条消息、目录或会话 ID 搜索，多个关键词同时匹配。
- `/sync`、`同步`：立即扫描；`/pause`、`暂停` 与 `/resume-sync`、`恢复`：暂停或恢复同步。
- @机器人 并直接写任务：作为新会话的任务，点选目录后开始（见“从飞书新建会话”一节）。

会话话题里：

- `/`：在话题最新处再发一张控制卡片，按钮与根卡片相同。
- `/stop`：停止当前回合；`/export`：导出完整记录。
- `/ls [路径]`：查看会话目录（或指定目录）下的文件；`/ls -a` 同时列出以 `.` 开头的项。
- `/deliver <路径…>`：把本机文件发到话题里，例如 `/deliver report.md output/*.png`。
- `/status`：同 `/`；`/model`：模型和推理强度卡片；`/mode`：权限模式卡片；`/help`：帮助卡片。这几个命令由桥接回卡片，不会交给 Claude，也不会切换控制权。
- 只能在终端里使用的 Claude Code 命令（如 `/config`、`/login`、`/mcp`、`/permissions`）：桥接直接回复“只能在电脑上使用”。
- 以 `>>` 开头的消息：排队，等这一轮结束后再发给 Claude。
- 其它所有内容（包括 `/compact` 等以 `/` 开头的内容）都原样交给 Claude。
- 话题里的命令处理出错时，话题里会收到“处理失败”和原因。

### 机器人菜单

安装器不会自动配置机器人菜单。需要时在飞书开发者后台的“机器人 → 自定义菜单”里手工添加，菜单项类型选“事件”，事件键用：`claude.home`（控制台）、`claude.new`（新建会话）、`claude.sessions`（最近会话）、`claude.search`（搜索会话）、`claude.service`（控制台）。改完后重新发布应用版本。不配置菜单不影响其他功能，发送 `/` 同样能打开命令菜单。

### 查看和发送本机文件

在会话话题里发送 `/ls`，桥接回一张“目录内容”卡片：先列子目录，再列文件（大小、修改时间），最多 80 项。路径规则与 `/deliver` 相同，只能查看 `ALLOWED_ROOT` 以内的目录，`.git`、`.ssh`、`.config`、`.claude` 等目录不开放。卡片上的按钮：

- 子目录名（最多 12 个）：在原卡片上进入该目录；
- “上一级”“会话目录”：返回上一级或会话的工作目录；
- “发送本目录的文件”：等同于 `/deliver <这个目录>`。

在会话话题里发送 `/deliver <路径…>`，桥接先回一张“交付文件”卡片，列出要发送和不发送的文件，再把文件逐个发到话题里。

- 路径相对会话目录，也可以写绝对路径或 `~/` 开头的路径；多个路径用空格分开，含空格的路径加双引号。
- 可以是文件、目录或通配符。目录只发其中的文件，不展开子目录，也不发 `.` 开头的文件。
- PNG、JPEG、GIF、WebP、BMP 图片（不超过 10 MB）作为图片消息发送，其余作为文件消息发送。手机上实测，Markdown、CSV、JSON、代码、HTML、PDF 文件都能直接预览；SVG 不能作为图片发送，作为文件发送时手机上也不能预览，需要先另存为 PNG。
- 每次最多 20 个文件，单个文件不超过 30 MB（飞书的上限）。空文件、`ALLOWED_ROOT` 以外的文件、文件名像密钥或凭据的文件（如 `.env`、`*.pem`、`id_rsa`），以及 `.git`、`.ssh`、`.config`、`.claude` 等目录里的文件都不会发送，卡片里会说明原因。
- 不需要新增飞书权限，用的是已有的 `im:resource`。

中文快捷词只在群主消息中生效。

## 同步哪些内容

发送到飞书的只有：你的提问（去掉 IDE 自动附加的打开文件、选中内容等上下文）、Claude 的文字回复、工具调用的一行摘要（命令的第一行、文件路径、搜索关键词等）及其成功或失败。不发送 thinking、工具的完整输出、子 agent 的过程和原始 JSONL。

从飞书继续的会话还会发送需要你处理的卡片：权限确认卡片显示这次工具调用的内容（例如要执行的命令、要修改的文件和改动），提问卡片显示问题和选项，计划卡片显示计划内容。

## 运维

```bash
npm run doctor:claude                                   # 只读自检
npm run check:cards                                     # 让飞书校验 Claude 和 Codex 的全部卡片，不向任何群发送消息
systemctl --user status feishu-claude-bridge.service
journalctl --user -u feishu-claude-bridge.service --since today
```

- 状态数据库：`~/.local/state/feishu-claude-bridge/bridge.sqlite`。
- **从飞书继续的会话如何运行**：每个会话由一个 `claude` 进程处理。进程空闲 `RUNNER_IDLE_MS` 毫秒（默认 600000，即 10 分钟）后退出，下一条消息会自动重新接上这个会话（resume）。进程异常退出时，话题里会有提示，再发一条消息即可重新启动。服务停止时，会先中断正在进行的回合。
- **相关的环境变量**（在 `~/.config/feishu-claude-bridge/env` 中，修改后重启服务）：
  - `CLAUDE_BIN`：从飞书继续的会话所用的 `claude` 可执行文件。
  - `ALLOWED_ROOT`：从飞书新建会话时，目录必须是它或它的子目录，默认是主目录。
  - `RUNNER_IDLE_MS`：`claude` 进程空闲多久后退出，单位毫秒，默认 600000。
  - `PATH`：安装器写入的安装时 shell 的 `PATH`，见下一条。
- **服务配置**：Claude 桥接的 systemd 用户服务不使用独立的 `/tmp`（不启用 `PrivateTmp`），并使用安装时 shell 的 umask；安装器还会把安装时 shell 的 `PATH` 写进环境文件。这样，从飞书继续的会话里执行的命令，看到的 `/tmp`、创建文件的权限和能找到的可执行程序，都与在终端里一致。修改了 shell 的 `PATH` 或 umask 后，重新运行 `./install-claude.sh` 即可（会复用已有的飞书应用、绑定和 hook）。
- 出于安全考虑，服务仍保留 `NoNewPrivileges` 等限制，因此从飞书继续的会话里不能使用 `sudo`。
- WSL 需要保持运行；systemd 用户服务在没有登录会话时会停止，可以执行 `sudo loginctl enable-linger $USER` 让它常驻。
- 会话日志格式属于 Claude Code 内部实现，会随版本变化。解析器对未知记录一律忽略；升级 Claude Code 后如发现显示异常，先运行测试，再检查 `src/claude/transcript.ts`。

## 实现位置
